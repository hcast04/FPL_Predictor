## 0. TOMORROW'S PRIORITY — why were GW6 and GW7 so hard?

Three independently-built squads collapsed in the same two gameweeks while the
crowd held up. That is a stronger signal than any single model result.

| GW4-7 | total | vs average |
|---|---|---|
| FPL average | **234** | — |
| our model | 175 | -59 |
| the user | 169 | -65 |
| legacy pipeline | 162 | -72 |

GW6-7 alone: model 62, legacy 57, user 67, **average 117**.

### What is already measured
- **No fixture weirdness.** Zero double gameweeks in 2026-27 so far; player
  counts per gameweek are flat (610-668). Not a blank/double effect.
- **Ownership bands, GW6** (using CURRENT ownership -- see the caveat):
  `>50%` owned averaged **9.0** pts, `30-50%` **8.6**, `<5%` **1.43**. A ~6x
  differential across 427 low-owned players.
- **Legacy made the same mistakes we did.** It captained Bruno Fernandes in 3
  of 4 gameweeks for 2, 2, 1 points. Our model captained Bruno every week for
  1, 1, 2. Two separate pipelines, same error.
- **Our GW6 XI scored 25.** The 11 most-owned players scored 83 that week.

### The trap to avoid (M19)
The ownership figures above come from `selected_by_percent`, captured AFTER
GW7. Managers buy players who have scored, so "highly owned" is partly a
restatement of "scored well". A whole feature-engineering effort (F23, -83
pts/season) was built on that artefact before it was caught.
**O36 blocks this: `live.py` does not capture contemporaneous ownership.**
Add `selected_by_percent` to the live collector FIRST, or any GW6-7 ownership
analysis repeats the same mistake.

### Angles not yet tried
1. **Per-player attribution.** For GW6 and GW7, decompose the gap: which
   specific players did the average own that all three squads missed, and were
   they ownable (price, availability) at the GW5/GW6 deadlines?
2. **Was it predictable at all?** Compare each model's xP for the GW6-7 top
   scorers against their realised points. If the models rated them correctly
   but did not OWN them, it is a selection/budget problem. If they rated them
   low, it is a forecast problem. These need different fixes.
3. **Check the user's own squad** via the entry history API -- `picks` per
   gameweek are available and would show whether the user, the model and
   legacy failed on the same players or different ones.
4. **Variance check.** Two bad weeks in seven is not obviously abnormal. The
   per-gameweek sd of the model's score across holdout seasons would say
   whether 30 and 32 are outliers or ordinary tails.
