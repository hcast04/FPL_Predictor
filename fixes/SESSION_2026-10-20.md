## What was built

`fpl2/` — 8 modules, 57 passing tests, ~1,500 lines. The old pipeline is
untouched and still produces the weekly recommendation.

| module | role |
|---|---|
| `config` | FPL rules and paths, no logic |
| `data` | canonical panel, one row per player-gameweek; coverage mask |
| `optimise` | exact MILP squad; best XI verified against brute force |
| `simulate` | season under real constraints; `signal` and `actual` always separate |
| `noise` | **the ruler** — built before anything it measures |
| `features` | 100 strictly-lagged features; leakage enforced by test |
| `scoring` | FPL rules, **99.41% exact** reconstruction of four seasons |
| `minutes` / `rates` / `team` / `external` | the component model |

**Noise floor: ~148 points.** A season-total delta below that is not a result.
Independently reproduced from a prior session's ~150.

## What worked

1. **xG/xA instead of goals/assists** (user's idea). Smoother (sd/mean 2.09 vs
   3.11) and more predictive (corr 0.263 vs 0.241). Captain gap on clean folds
   went -127 → -10 and -85 → -28.
2. **xGC instead of goals conceded** for clean sheets (user's idea). AUC
   +0.017 / +0.027 where training data is clean.
3. **Coverage mask** on 2022-23 gameweeks 1-15, where xG was never collected
   (100% zeros). Calibration ratios → 0.958 / 0.971 / 1.033.
4. **Season-stage feature.** `season_appearances_so_far` means "opening
   weekend" at GW1 and "never selected" at GW20; without `gameweek` the model
   could not tell them apart and under-predicted cold-start appearances by 18%.
   Fixed: GW1 p_appear 0.353 → 0.439 against an actual 0.433.
5. **Defensive-contribution rule derived from data**, not read from a rules
   page: DEF ≥10, MID/FWD ≥12 actions, 2 points — each threshold carried a mean
   signed error of exactly -2.000.

And **~85% of the within-squad gap is the captain** — XI points excluding the

New-to-PL ratio, GW1-6 (1.000 = perfectly calibrated):

| season | before | after | note |
|---|---:|---:|---|
| 2023-24 | 0.977 | 0.980 | no priors in this fold (trains on 2022-23) |
| 2024-25 | 0.972 | **1.000** | exact |
| 2025-26 | 0.929 | **0.952** | |
| 2026-27 | 0.834 | 0.847 | only 42% points coverage |

Mover flags: spearman essentially unchanged (0.454/0.465/0.622/0.525 ->
0.446/0.473/0.610/0.527) and calibration WORSE in 2024-25 (1.075 -> 1.228).

**G8 FAILS its declared mechanism gate** -- 2026-27 moved 0.834 -> 0.847, not
"material". But the reason is coverage, not the idea: that is the season where
58% of new-arrival points belong to unmatched Championship players.

**Decisions:** keep the external priors (they calibrate exactly where data
exists). Drop the mover flags unless a better specification is found -- a flag
IDENTIFYING a group is not the same as a CORRECTION for its bias, and four
features on ~60 players per season is thin evidence.

## Process lessons that cost real time today

- **Self-matching `pgrep`/`pkill` — four times.** A waiter whose command line
  contains its own search pattern never exits; one silently stopped G1 running
  at all, another discarded a script before it was written. **Poll log file
  contents, never process names.**
- **`str.replace` with a computed slice.** `s[s.index(a):s.index(b)]` returned
  "" because b preceded a, and `replace("", x)` inserts between every
  character — an 8KB source file became 20MB. Edit with anchored exact matches.
- **`| tail` destroys run visibility** — it buffers until the process exits, so
  a 45-minute run shows nothing and cannot be monitored.
- **Background tasks die with the session.** Two long runs were lost. Write
  intermediate results to disk as they are produced.
